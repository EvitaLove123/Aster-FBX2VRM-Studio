3. Humanoid & finger mapping

Map bones before exporting. VRM export requires the core humanoid bones; review Auto-Mapping before downloading.

Load an FBX model to detect bones.

4. Material editor

Preview-only material controls. These settings are exported only where the GLTF exporter can represent them; VRM-specific MToon properties are not yet authored.

5. VRM metadata

Model name and author are required for both export formats. Choose permissions carefully; they are written into the exported VRM metadata.

6. VRM export

Exports a binary GLB container with VRM extension data and the .vrm file extension. Core humanoid mapping is required. Advanced features such as MToon authoring, expressions, first-person mesh annotations, SpringBone and colliders are not yet included.

Load a model and complete required humanoid mapping to export.

7. Prototype status

  • FBX file selection and local ArrayBuffer parsing
  • External image selection with filename-based URL matching, including reloading after textures are added
  • Mesh visibility recovery and double-sided material preview
  • Experimental Auto T-pose for recognized upper-arm, forearm, and hand bones
  • Three.js 3D scene with lighting, grid, axes, and responsive resize
  • Orbit, zoom, pan, automatic framing, and camera reset
  • Basic mesh, material, and skeleton inspection

This is an early FBX-to-VRM exporter. It writes a GLB binary with a VRM 0.x or VRM 1.0 core extension, based on the mapped humanoid skeleton. Advanced VRM features are not yet included; validate each exported model in a VRM validator and target app.
